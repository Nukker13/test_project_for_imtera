# Требования

Пересказ исходного ТЗ своими словами и решения, принятые до начала работы.
Это входные данные, от которых строились план и код. Как решение отвечает на каждый
пункт, описано в [README](../README.md).

## Задача

Веб-приложение принимает ссылку на карточку организации в Яндекс.Картах, собирает
отзывы и показывает их пользователю.

**Стек по ТЗ:** Laravel + Sanctum, Vue 3 (Composition API), сборка и запуск через
docker-compose.

### Интерфейс

* Две страницы: логин и «настройки организации + данные».
* Логин — обычная форма email + пароль под seed-пользователя. Регистрация не нужна,
  но выглядеть форма должна как настоящая.
* Ссылка валидируется, организация заводится в БД.
* Выводятся все отзывы, по 50 на страницу. У каждого отзыва — дата, текст, оценка
  и автор.
* Средний рейтинг из Яндекса, а также количество оценок и количество отзывов —
  **раздельно и точными числами**.
* Состояния загрузки и ошибок видны в интерфейсе.

### Парсер

* Принимает ссылку на любую организацию.
* Собирает все доступные отзывы. Ориентир работодателя — до ~600 на карточку.
* Работает порциями по 50–100 через очередь.
* Повторный парсинг той же организации обновляет данные, а не создаёт дубликат.
* Данные только реальные, из карточки, ничего не досочинять.
* **Ключевое требование:** обходит антибот-защиту Яндекса. Предложенная связка:
  Playwright/Patchright проходит JS-челленджи и добывает cookies, `csrfToken` и
  `sessionId`, затем curl_cffi с TLS-отпечатком Chrome ходит напрямую в
  `fetchReviews`.
* Логика работы с внешним источником вынесена из контроллеров и сервисов Laravel.
* При отсутствии данных или смене разметки парсер сообщает об ошибке, а не
  молча возвращает пустоту.

### README должен объяснять

Как поднять проект; почему выбран такой алгоритм и чем он лучше альтернатив; как
парсер понимает, что сломался, и что делает дальше; масштабирование; защиту от
бана при регулярном парсинге; что можно развивать дальше.

## Решения, принятые до начала работы

Срок был около суток, поэтому приоритеты зафиксировали заранее.

* **Фокус** — рабочий обход антибот-защиты. Остальное при нехватке времени можно
  упрощать.
* **Архитектура:** парсер — отдельный Python-сервис со своим HTTP API, Laravel
  ходит к нему по сети. Очередь — Redis + Laravel Queue, воркер в отдельном
  контейнере. БД — PostgreSQL.
* **Модель данных:** upsert по внешним id организации и отзыва, плюс лог прогонов
  `parse_runs` со статусом и метаданными. Версионных снимков нет. Перепарсинг —
  только вручную, без cron.
* **Ошибки:** при бане, капче или смене разметки прогон получает статус `failed`,
  а понятный текст показывается в UI. Автоматических ретраев нет.
* **Защита от бана:** в коде только паузы между запросами внутри прогона.
  Ротация прокси/UA и троттлинг подробно описываются в README как план.
* **Тесты:** автотесты в рамках срока не пишутся.
* **Эталон для проверки:** карточка `https://yandex.com/maps/-/CTxMzF5W`.
